## [RFC 10008 提出新的 HTTP QUERY 方法，用于带请求体的幂等查询](https://www.rfc-editor.org/info/rfc10008/) ⭐️ 8.0/10

刚刚发布的 RFC 10008 提出了一种新的 HTTP QUERY 方法，允许客户端发送带有请求体的幂等且安全的请求，用于查询服务器端数据而无副作用。 这填补了 GET（无请求体）和 POST（非幂等）之间在复杂查询上的长期空白，使得 API 设计能够拥有更好的缓存语义和安全的幂等操作。 QUERY 方法要求既是安全又是幂等的，不同于 POST；缓存语义将请求体视为缓存键的一部分，可能导致无界缓存键。RFC 还讨论了流式传输和 HTML 表单的影响。

hackernews · schappim · Jun 17, 10:51 · [社区讨论](https://news.ycombinator.com/item?id=48568502)

**背景**: 现有的 HTTP 方法包括 GET（安全、幂等、无请求体）和 POST（不安全、非幂等）。对于需要请求体的复杂查询，开发者常滥用 POST，破坏了幂等性和缓存。新的 QUERY 方法旨在通过提供带有请求体的安全、幂等方法来解决这一问题，类似于 GET 但带有负载。

## [Hugging Face 推出自主资源发现](https://huggingface.co/blog/agentic-resource-discovery-launch) ⭐️ 8.0/10

Hugging Face 推出了一种名为“自主资源发现”的新方法，使 AI 代理能够自主搜索和检索外部能力，如 API、MCP 服务器和其他代理。 这项创新简化了工作流中多样化 AI 资源的集成，使得在去中心化环境中实现更自主、更灵活的 AI 系统成为可能。 根据规范，自主资源是 AI 客户端可以调用的任何外部能力，包括代理、MCP 服务器、技能、API 和工作流，资源发现在调用前帮助定位正确的资源。

rss · Hugging Face Blog · Jun 17, 00:00

**背景**: 大规模自主系统通常运行在分布式基础设施上，其中许多软件代理共享主机并需要动态发现彼此。传统的发现方法可能无法很好地处理代理级别的变动，导致效率低下。自主资源发现通过启用自主搜索和检索资源来解决这一问题。
